# archive-ops-demo

一套面向个人 AI 工作环境的备份与变更管理。目标很窄:降低重要记录丢失、以及配置改动失控的风险。

## 它做不到什么(先看这三行)

- **不做同一时刻快照** —— 检查期间别同时改源目录,否则结论不可靠;
- **回滚清单为空时判为"未检测"** —— 那只代表"没有资源可验证",不代表"回滚能力已验证",也不会算失败;
- **不跟随符号链接目录** —— 目录树里有链接时,不保证遍历完整(见 `DESIGN.md` L4)。

完整的限制清单、优先级与重新评估条件在 [`DESIGN.md`](DESIGN.md)。

## 做哪几件事

**备份要看结果,不能复制完就算。**
每次备份会把源目录里每个文件和备份里的同名文件比大小、比 SHA-256。缺文件、哈希对不上,都会单独列出来。备份目录里多出来的文件只提示,不算失败。跑完打印各计数,或者具体是哪几个不对。

**改动前后都留证据。**
升级软件、改配置之前,先把当前会话存储和档案复制一份,记下哈希,再动手。装完再对一次,看有没有计划之外的改动。会话存储这一块别的备份不覆盖,所以单独做。

**坏了能退。**
每个已安装版本都保留对应的安装包及其 SHA-256 校验值 —— 这是原系统的做法,演示版只演示"按清单核对哈希"这一步。截至 2026-11-21,原系统保留了九个历史版本。

**一条命令能一次检查完。**
原系统约二十项:备份是否忠实、文档结构是否完整、回滚资源在不在、有没有未提交的改动。跑完汇总通过项、失败项及失败原因。

这个仓库的演示版实现了其中四项,分别是备份一致性、Markdown 格式、回滚清单哈希、Git 工作区状态。四项之外的能力不在这个仓库里。

## 验证过的事

判断标准不是"有没有报错",是"抓不抓得到问题"。三次记录如下。

**一次备份里,六个文件和源目录不一致。** 是 `verify` 报出来的,不是翻日志时发现的。当时改的是档案里的文档,备份没跟上。

**一次配置修改,让界面无法显示也无法输入。** 删一个配置条目时只删了它的第一行,下面那行缩进的开关留在了原地,于是那行开关被算进了上一个条目,把界面主题关掉。这个配置文件是热加载的,存盘的瞬间界面变成纯白。恢复靠的是改动前留下的那份带哈希的备份;恢复之后,界面还要等软件重启才回来。

**一次升级,对比输出里多出两个变化。** 预期只有一个插件版本变化,实际多了两项;查下去是同时装的另一个插件。这次没有出事,但确认了"只看安装成功不够,要看变化清单"。

## 出过的错

上面第二件事的影响最大。直接原因是删配置条目只删了一行,下面那行开关被算进了上一个条目。

现在有三条固定动作:删条目删整块;存盘后检查相邻条目有没有被牵连;改完要说清楚"这一步之后需要重启"。

## 运行方式

检查脚本可以独立运行;示例数据由另一个脚本生成。

```
python make_samples.py          # 生成示例数据(故意含缺陷:缺文件、内容不一致、回滚包缺失)
python check_all.py --source samples/source --backup samples/backup --rollback samples/rollback
```

示例数据下的实际输出:

```
[备份] 一致 1 个 · 缺失 1 个 · 不一致 1 个 · 备份多出 1 个
        缺失: table.md
        不一致: plan.txt
        仅存在于备份: extra.md(不算失败,仅提示)
[文档] 结构检查 2 篇 · 通过 2 · 失败 0(只查格式,不查内容)
[回滚] 安装包 2 个 · 合格 1 · 缺失 1 · 未填哈希 0 · 哈希不符 0 · 路径越界 0
        tool-2.0.bin: 文件缺失
[Git ] 未检测:该目录不是 Git 仓库

结果: 2 项未通过 · 1 项未检测
```

退出码:0 全部通过,1 有失败项。示例数据是故意做的缺陷,所以这里退出码是 1。

**四项检查的对象是分开的:**

| 检查 | 对象 | 参数 |
|---|---|---|
| 备份 | 源目录与备份目录 | `--source` / `--backup` |
| 文档 | Markdown 目录 | `--docs`(默认取 `--source`) |
| 回滚 | 回滚资源目录 | `--rollback` |
| Git | 项目仓库根 | `--git-root`(默认脚本所在目录) |

**关于 Git 检查:** 调用本机 `git status --porcelain` 读取工作区。**目录不是 Git 仓库、或本机没有 git 时,报告"未检测"并计为跳过,不会当成通过。**
**汇总输出分三种:**全部通过 / 无失败项 · N 项未检测 / N 项未通过。[有未检测项时不会写成"全部通过"。]

## 这些检查能证明什么、不能证明什么

- **备份检查**:证明源目录里每个文件在备份里存在且逐字节一致;**不检查备份目录里多出来的文件是否是垃圾**,只提示;
- **文档检查**:只查**末尾换行、前五行有标题、代码围栏成对**;**不检查内容正确性**;**目录里一个 Markdown 都没有时,报"未检测",不报通过**;
- **回滚检查**:证明清单里登记的安装包存在、且哈希匹配;**清单没填哈希的会单独报"未填哈希"**,不算合格;清单里的路径必须是回滚目录内的相对路径,**绝对路径或用 `..` 跳出去的会被拒绝并报"路径越界"**;
- **Git 检查**:证明工作区没有未提交改动;**git 不可用时不作结论**;`.git` 无论是目录还是文件(worktree 形式)都会被识别,识别后仍交给 git 命令判断。

## 验证检查本身

```
python self_test.py
```

会在临时目录里造十一组场景,每项都有明确断言,任何一项不符合预期就返回非零退出码:

示例数据本身 · 清单缺哈希 · 备份多出文件 · 文档缺末尾换行 · 空文档目录 · 清单 `..` 越界 · 链接指向目录外 · Git 干净与脏 · 真实 worktree · `.git` 是文件 · 三种汇总语义。

其中"链接指向目录外"在 Windows 上先试符号链接,普通账户建不了符号链接时退用目录联接(junction),两者都能穿出目录;两种方式都不可用时会明确标为跳过,不会静默当成通过。

环境要求:**Python 3.9 以上**;除 Git 检查外只用标准库,不联网。

关于 3.9:代码里的类型注解用了 `str | None` 这种写法。因为两个文件开头都有
`from __future__ import annotations`,注解不会被求值,所以按语言机制 3.9 可以运行。

**尚未在真实的 3.9 解释器上运行过。** 目前做的是语法层面验证:
用 `ast.parse(..., feature_version=(3, 9))` 对三个脚本做 3.9 语法检查,均通过。
如果部署环境确实是 3.9,建议先跑一次 `python self_test.py` 再使用。

## 目录结构

```

make_samples.py         生成示例数据(不含真实内容)
self_test.py            十一组反例与边界测试,验证检查本身有效
samples/source/         示例源目录
samples/backup/         示例备份(故意缺一个、改一个、多一个)
samples/rollback/       示例回滚清单(故意登记一个不存在的包)
docs/01-变更流程.md      快照 → 改动 → 对比 → 回退,每步带判据
docs/02-事故记录-示例.md  一份脱敏的事故记录
docs/03-检查器缺陷与复核.md  检查器自身出过的五类缺陷、怎么发现、怎么修、怎么验
LICENSE                 MIT
```

这套系统是本人和 AI 助手一起做的。决定由本人下,代码大部分由 AI 写,验收、发现问题、记录错误由本人做。上面那个把界面弄没了的错误也记在案里,没有删掉。

## 设计说明与已知限制

想快速了解**设计取舍**和**它做不到什么**,看 [`DESIGN.md`](DESIGN.md):四项检查各自的边界、
"通过 / 失败 / 未检测"三态的含义、以及四条已知限制(不做同一时刻快照、空清单语义待定、
不跟随符号链接、不是生产工具)。

**其中一条要特别注意**:检查期间不要同时改动源目录与备份目录 ——
本工具先取文件大小、再算 SHA-256,没有快照机制,并发修改会让结论不可靠。
